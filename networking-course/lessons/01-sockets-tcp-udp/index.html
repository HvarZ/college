Основы

Сокет = IP-адрес + порт

интернет
Сервер

  • IP-адрес — где: какой компьютер в сети
  • порт — кому: какая программа ждёт данные (0–65535)
80 HTTP 443 HTTPS 25 SMTP 53 DNS
Аналогия: IP-адрес — адрес дома, порт — номер квартиры. Письмо дойдёт до дома, а квартиру выбирает порт. Клиентский порт обычно случайный (динамический, 49152–65535), серверный — известный заранее: 443 для HTTPS, 80 для HTTP. 40 лет без изменений

Один и тот же API прожил эпохи:
C → C++ → Java → Python → Go

socket — англ. «разъём»: воткнул провод — есть соединение

История для настроения: 1983 год, Билл Джой пишет сокеты для Berkeley UNIX, заодно TCP/IP. Через это «всё есть файл» — сеть как файловый дескриптор. Именно поэтому socket API везде одинаковый: Java Socket, Python socket — это обёртки над тем самым API из 1983 года.

Socket API

Жизненный цикл: сервер и клиент

Сервер socket→ bind→ listen→ accept→ recv / send→ close
Клиент socket→ connect→ send / recv→ close

Одни и те же шаги — в любом языке: C, Java, Python

Пройти верхнюю линию: bind — «занять порт», listen — «встать в очередь ожидания», accept — «взять трубку». [FRAGMENT] Клиент проще: socket → connect — и уже можно слать байты. [ЕСЛИ ГРУППА СИЛЬНАЯ] нажать ↓ и показать Java-код целиком; слабой группе — показать на практикуме.

↓ Доп. факт

Тот же echo-сервер на Java

try (ServerSocket server = new ServerSocket(8080)) {  // bind + listen
    System.out.println("Жду клиента на :8080");
    while (true) {
        Socket client = server.accept();            // ждём соединения

        new Thread(() -> {                          // каждому клиенту — поток
            try (Socket c = client) {
                var in  = c.getInputStream();       // recv
                var out = c.getOutputStream();      // send
                int b;
                while ((b = in.read()) != -1) {
                    out.write(b);                   // эхо-ответ
                }
            } catch (IOException e) { /* клиент ушёл */ }
        }).start();
    }
}
Обратить внимание: ServerSocket прячет socket+bind+listen в один вызов конструктора. Этот код — заготовка ПР №60: на практикуме соберём его с нуля шаг за шагом и проверим через telnet.

Транспортный уровень

TCP: рукопожатие перед разговором

Аналогия телефонного звонка: «Алло?» — «Да, слушаю» — «Отлично, начинаем». Только роли SYM/ACK. Три пакета — и только потом данные. Зато дальше TCP гарантирует: всё дойдёт и в правильном порядке. Связать с предыдущим слайдом: SYN и ACK на диаграмме — это биты в поле флагов; seq/ack из «рукопожатия» живут в синих ячейках. Окно — «сколько ещё влезет»: получатель сообщает отправителю свой буфер. Это управление потоком.

Итог

TCP или UDP?

TCP — надёжный

  • соединение: handshake перед данными
  • всё доставляется, в правильном порядке
  • потерялось — перешлёт заново
  • HTTP, почта, файлы, мессенджеры

UDP — быстрый

  • без соединения: сразу шлём
  • без гарантий доставки и порядка
  • зато никаких задержек
  • DNS, игры, стриминг, VoIP

Выбор — надёжность против скорости.
