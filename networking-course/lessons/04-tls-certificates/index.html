TLS и сертификаты

Как браузер понимает, что говорит именно с вашим банком, а не с самозванцем

Введение

Три угрозы открытого канала

Подслушать

посредник читает трафик: пароли, карты, cookie — как открытую книгу

Подменить

данные меняются в пути: сумма перевода, ответ API, страница

Притвориться

«сайт» — самозванец: внешний вид тот же, сервер чужой

HTTP — открытый текст: в чужом Wi-Fi ваш запрос виден целиком (урок 02)

TLS закрывает все три: шифрование · целостность · подлинность.

Введение

От SSL к TLS

1999

TLS 1.0

стандарт IETF; «переименование» SSL → TLS

TLS 1.2

Слово «SSL» живёт в настройках и логах; сам SSL 3.0 отключён после атаки POODLE (2014), TLS 1.0/1.1 браузеры убрали в 2020

Криптография

Симметричное: один ключ

Как работает

  • один ключ шифрует и расшифровывает
  • AES — стандарт; в процессорах есть аппаратное ускорение
  • скорость — гигабиты в секунду: шифруем весь трафик

Проблема

  • ключ должен быть у обеих сторон
  • передать его по открытому каналу нельзя — его услышат
  • сменить по договорённости «заранее» — для миллиарда незнакомцев не выйдет
AES-128 · AES-256 · ChaCha20 если ключ один — это симметрия

Симметрия — быстро и просто, но ключ надо как-то передать.

Криптография

Асимметричное: пара ключей

публичный

замок 🔓

раздавайте кому угодно

пара

приватный

ключ 🔒

хранить в тайне всегда

  • Что зашифровано публичным — расшифрует только приватный
  • Математика: RSA (1977) и эллиптические кривые (ECC)
  • Медленнее симметрии на порядки → в TLS используется только для ключей и подписей

Публичный ключ можно «повесить на забор»: секрета в нём нет — без приватного он бесполезен

Криптография

Гибрид: лучшее из двух

асимметрия: обмен долями ключа→ у обоих одинаковый сеансовый ключ→ симметрия: шифруем все данные
  • Асимметрия решает главную проблему — как договориться о ключе по открытому каналу
  • Сеансовый ключ живёт одно соединение: новая сессия — новый ключ
  • Итог: скорость AES + безопасная передача ключей без предварительной встречи

Так работает и рукопожатие из урока 02 — теперь видно, что там происходило

↓ Доп. факт

Подпись: шифрование наоборот

  • Хеш — «отпечаток» документа фиксированной длины: меняется от малейшей правки
  • Подпись = хеш, зашифрованный приватным ключом; проверить может любой — публичным
  • Подпись доказывает сразу два: документ не менялся и подписал владелец приватного ключа
  • Это и есть механизм сертификатов: центр сертификации подписывает их своими ключами — дальше по слайдам

Механика

Рукопожатие TLS 1.3

TCP-рукопожатие (урок 01)→ ClientHello: шифры + доля ключа→ ServerHello: шифр + доля + сертификат→ оба вычисляют сеансовый ключ→ зашифрованные данные
  • Ключи не передаются — каждая сторона вычисляет их из долей (математика Диффи–Хеллмана)
  • Сервер доказывает личность сертификатом — тема следующей части
  • Весь обмен — 1 круг (RTT); в TLS 1.2 требовалось два

↓ Доп. факт

0-RTT: данные в первом же пакете

  • Возобновление: вы уже ходили на сайт — есть «память» прошлой сессии
  • 0-RTT: запрос летит вместе с ClientHello, без ожидания ответа сервера
  • Подвох: пакет можно повторно воспроизвести — ранние данные годятся для GET, но не для POST «оплатить»
  • Знакомое слово из урока 02: идемпотентность — вот где она решает

Сертификаты

Сертификат: паспорт сервера

Subject
кому выдан: домен, организация
SAN
все имена, которые сертификат обслуживает; wildcard: *.example.com
Issuer
кем выдан — центр сертификации
Validity
NotBefore → NotAfter: срок действия
Public key
публичный ключ сервера
Подпись
подпись издателя: паспорт не самодельный

Формат называется X.509. Посмотреть любой: в браузере — замок → «соединение защищено» → сертификат

Сертификаты

Цепочка доверия

Корневой CA — ISRG Root X1, DigiCert Global Root… · ключ офлайн, в сейфе · 10–25 лет

↓ подписал

Промежуточный CA — R11, GTS CA 1C3 · выдаёт сертификаты миллионам сайтов

↓ подписал

Сертификат сайта — example.com · дни-месяцы · выдаётся автоматически

Промежуточное звено — защита корня: скомпрометировали звено → отзывают только его; корней ~150, и они зашиты в хранилища ОС и браузеров

↓ Доп. факт

DV, OV, EV: глубина проверки

DV

«домен ваш»: проверка автоматическая, минуты; так живёт большинство сайтов

OV

проверена организация: её имя — в сертификате

EV

строгие проверки; раньше давали «зелёную строку», ныне браузеры не выделяют

  • Замок в браузере у всех трёх одинаковый — тип сертификата о честности сайта не говорит

Сертификаты

Что проверяет браузер

1 · Цепочка

сходится к корню из хранилища ОС/браузера

2 · Срок

сейчас между NotBefore и NotAfter

3 · Имя

набранный домен входит в SAN

4 · Подписи

каждого звена верны, ничего не отозвано

  • Любой пункт «нет» → страница-предупреждение, а не сайт
  • Всё это — миллисекунды при каждом HTTPS-соединении, без участия пользователя

Wildcard *.example.com покрывает все поддомены одного уровня: a.example.com — да, x.a.example.com — нет

↓ Доп. факт

Инцидент в 03:00 ночи

  • У сертификата есть NotAfter — и он наступает: сайт становится «небезопасным» посреди ночи, без взлома
  • Продление должно быть автоматическим, а сроки — под мониторингом с alarmами за неделю
  • Домен из урока 03 и сертификат — два разных продления: домен оплачен, а сертификат просрочен — классика
  • Лечится минутой: certbot renew — но кто-то должен был её настроить

Демонстрация

Сертификат в терминале

# цепочка и статус проверки живого сайта
openssl s_client -connect example.com:443 -servername example.com

# три главных поля: кому, кем, до каких пор
openssl s_client -connect example.com:443 -servername example.com </dev/null \
  | openssl x509 -noout -subject -issuer -dates

# рукопожатие глазами curl: версия TLS и шифр
curl -v https://example.com -o /dev/null
Windows: openssl есть в Git Bash браузер: замок → сертификат DevTools → Security

Паспорт любого сайта — в открытом доступе.

Разбор вывода s_client

Три глубины — та самая цепочка со схемы; код 0 — чек-лист браузера, выполненный openssl

Безопасность

Атаки: посредник и подмена

MITM: «Free Airport Wi-Fi»

  • HTTP: посредник читает и правит всё
  • HTTPS: видит только домен (SNI) и объём
  • расшифровать — не может

Подмена DNS (урок 03)

  • vk.com уведён на адрес фейка
  • но сертификата для vk.com у фейка нет
  • браузер закричит → TLS — последняя линия

TLS превращает подмену из незаметной в громкую.

↓ Доп. факт

Heartbleed, 2014

  • Баг в реализации OpenSSL (механизм heartbeat): на запрос «покажи N байт памяти» сервер отдавал больше, чем просили
  • Утекала память сервера: ключи, пароли, сессии — без взлома криптографии
  • Протокол был цел: ошибка — в коде; лечится патчем, а не новым стандартом
  • Мораль: протокол силён ровно настолько, насколько исправна реализация — обновляйте библиотеки

Безопасность

Что замок не гарантирует

Честность сайта

фишинг тоже получает валидный DV-сертификат: замок — не репутация

Тайну метаданных

видны IP назначения, домен (SNI), объём и тайминги; ECH шифрует SNI — внедряется

Судьбу данных

TLS доставит пароль на сервер — а дальше зависит от сервера, не от протокола

Замок говорит: «канал до этого сервера защищён» — и только.

Глубже

mTLS: сертификат не только у сервера

Обычный TLS

  • сертификат предъявляет только сервер
  • клиент — «анонимный посетитель»
  • так работает весь веб

mTLS — взаимный

  • сертификаты у обеих сторон
  • выдаёт внутренний CA компании
  • сервис-сервис без паролей
  • Где встречается: внутренние API и микросервисы, банк-клиенты, Kubernetes
  • Идея та же, что у пропусков: не «кто ты по паспорту», а «твой пропуск подписан нашим CA»

Итог схемы

Весь путь — четыре урока на одной линии

DNS: имя → адрес→ TCP: рукопожатие→ TLS: ключи + сертификат→ HTTP: запрос — ответ
  • HTTP внутри не меняется — меняется обёртка: байты едут зашифрованными
  • TLS добавляет поверх TCP три свойства: шифрование · целостность · подлинность
  • Порт 443 — «обычный TCP-сокет» из урока 01, только с договорённостью TLS внутри

QUIC из HTTP/3 шифруется всегда — TLS 1.3 встроен в сам протокол

Итоги

Три главных вывода

Гибрид

асимметрия передаёт ключ, симметрия шифрует данные; сеансовый ключ — на одно соединение

Доверие — это цепочка

сертификат → промежуточный → корень из ОС; браузер проверяет её сам, за миллисекунды

Замок — про канал, не про сайт

фишинг тоже с замком; адрес и репутацию проверяют глаза, не браузер

HTTPS = HTTP + TLS: в формуле теперь понятны оба слагаемых.
